# NEAR Hackathon 开发构想：链上反诈情报网络

> 暂名：**BaitNet（诱饵网）**（名字可改）
> 比赛：NEAR Hackathon（nearhackathon.com）
> 截止：**2026-11-14 23:59 UTC**（北京时间 11-15 07:59）
> 文件日期：2026-11-09

---

## 1. 目的

**一句话**：让 AI 假扮受害者，从诈骗集团手里套出收款地址，再把这些地址实时广播给交易所、钱包、前端、RPC 和跨链桥。它们各自比对、各自报案，我们不碰任何用户个人资料。

要解决的问题：

1. **诈骗资金跑得比通报快**。受害者报案时，钱通常已经经过跨链桥、DEX 洗出去了。
2. **现有的情报网络只覆盖中心化交易所**。TRM Beacon Network、Tether/Tron/TRM 的 T3 FCU 能通知交易所和稳定币发行方冻结资金，但**跨链桥、DEX、NEAR Intents 做市商、钱包 App、RPC** 这些去中心化路径几乎没人管，骗子就是从这里洗钱。
3. **个人资料不能随便交换**。GDPR、中国的个人信息保护法、台湾的个资法都限制厂商把用户资料交给第三方，所以"集中收集资料再转交"这条路走不通。

我们的做法是：**我们只发布"诈骗地址加证据"，厂商自己比对、自己报案**。地址本来就是链上公开信息，用户资料从头到尾留在厂商手里。

## 2. 发想过程（我们是怎么一步步走到这个方案的）

1. **起点：先做 TapeSense（AI 交易 Agent），再看 NEAR 的赛道。**
   NEAR 的 13 个赛道里，NEAR 最想证明的一件事是"**AI 能安全地处理钱**"（06 AI Security & Defense），以及给 NEAR Intents 带来真实用途。

2. **参考案例：澳洲新创 Apate.ai。**
   - 它的 AI 用语音和文字假扮受害者，最长能拖住骗子两小时，同时收集钓鱼链接和人头收款账户，交给银行和电信。
   - 合作方有 TPG Telecom 和澳洲联邦银行，种子轮 815 万美元。
   - 我们看重的是：**能照抄、买方明确（银行、电信、交易所）、赚钱快（B2B 情报订阅）**。

3. **把 Apate 搬到链上。**
   - Apate 收集的是银行人头户，链上版收集的是**收款地址**。
   - 链上地址是公开的、可以追踪，资金流向可以跨链跟踪。

4. **第一版想法：要厂商交出设备和网络资料。**
   做法是通过跨链桥、交易所、钱包商拿用户的设备、IP 资料，再提供给电信、银行、政府。
   → **问题**：
   - 很多厂商根本没有这些资料，比如非托管钱包和 DEX 合约。
   - 有资料的厂商，没有法律依据也不能交出来。

5. **修正：改成订阅比对。**
   - 我们只发布诈骗地址，厂商订阅。
   - 地址一上链，终端厂商自己就能查到对应的设备和账户：
     - 交易所：充值地址直接对应到 KYC 账户。
     - 钱包 App：后端会记录地址对应哪台设备、哪个 IP。
     - 前端和 RPC：有日志就能查到 IP。
   - 命中后，厂商**自己**提交可疑交易报告或报案。
   - 我们看不到骗子"生成私钥"的那一刻，因为那是离线完成的。但这不影响比对，因为厂商可以往回查日志。

6. **"拒绝加入的厂商能被查到"怎么做才安全。**
   - 不贴"拒绝配合"这种标签，有诽谤和施压的风险。
   - 改成公开**可验证的事实**：
     - 某时刻发出警报
     - 资金在某时刻经过了哪个桥或哪个协议
     - 有没有回应、多久回应
   - 也就是一张公开的**响应记录表**。

7. **核实"Agent Market 能马上赚钱"的说法：不成立。**
   NEAR Agent Market 上卖方多、买方少，找不到可靠的成交数据。所以这个项目的商业模式不靠 Agent Market，而是 **B2B 情报订阅**。

## 3. 系统构想

```
 ┌────────────┐   诈骗对话    ┌──────────────┐
 │ 诈骗方      │ ◀──────────▶ │ ① 诱饵 Agent  │  假扮受害者，套出收款地址、钓鱼链接
 └────────────┘               └──────┬───────┘
                                     │ 抽取出的地址和证据
                                     ▼
                              ┌──────────────┐
                              │ ② 证据与分级   │  证据加密存放，算出 hash，标可信度等级
                              └──────┬───────┘
                                     │ report(address, chain, evidence_hash, level)
                                     ▼
                     ┌──────────────────────────────┐
                     │ ③ NEAR 警报合约 (Alert Registry) │  链上可查、不可篡改
                     └───────┬───────────────┬──────┘
                             │               │
                 ┌───────────▼──┐      ┌─────▼─────────┐
                 │ ④ 资金追踪     │      │ ⑤ 订阅端 SDK   │  交易所/钱包/前端/RPC/桥
                 │ 跨链跟踪去向   │      │ 本地比对→自行报案│
                 └───────┬──────┘      └─────┬─────────┘
                         │ 资金经过哪里        │ 匿名回报"命中/已处理"
                         ▼                    ▼
                     ┌──────────────────────────────┐
                     │ ⑥ 公开响应记录表 (Dashboard)    │
                     └──────────────────────────────┘
```

### 各模块说明

| # | 模块 | 做什么 | 比赛版范围 |
|---|---|---|---|
| ① | **诱饵 Agent** | 用 LLM 假扮受害者，按诈骗剧本（投资盘、杀猪盘、假客服）应对，目标是让对方给出收款地址和链接 | 用一个**模拟诈骗方 Agent** 和它对话（demo 不接真骗子），提供 Telegram 接口当作扩展 |
| ② | **证据与分级** | 从对话里抽出地址、链名、网址、电话。证据加密后放在链下，链上只存 hash。可信度分级：L1 诱饵对话直接取得 / L2 资金关联 / L3 聚类推测 | L1 和 L2 |
| ③ | **NEAR 警报合约** | `report()` 登记地址，`subscribe()` 让厂商订阅，`ack()` 让厂商匿名回报，`invite()` 邀请厂商加入。只有白名单里的回报者能写入 | 部署在测试网，Rust（near-sdk） |
| ④ | **资金追踪** | 从被标记的地址往后追资金：经过哪个桥、哪个 DEX、NEAR Intents、最后到哪个交易所 | 追 NEAR 和一条 EVM 链（或 Tron），加上 Intents 浏览器的资料 |
| ⑤ | **订阅端 SDK** | 厂商用 webhook 或轮询拿到新地址，跟**自己的**日志比对。命中后生成一份报案草稿给厂商自己用 | 用一个"假钱包后端"示范比对和命中流程 |
| ⑥ | **公开响应记录表** | 网页显示：警报时间、资金去向、各厂商有没有回应、多久回应 | 简单网页 |

### 用到的 NEAR 技术

- **NEAR 合约**：警报登记、订阅、回报、邀请记录。
- **NEAR Intents**：资金追踪的数据来源之一，因为跨链换币会经过这里。
- **NEAR AI Cloud / TEE（可选）**：诱饵 Agent 和证据处理放在 TEE 里跑，证明我们自己也看不到受害者资料。
- **function-call key**：给诱饵 Agent 一把只能调用 `report()` 的受限钥匙。

### 可以对应的赛道（还没决定）

- **06 AI Security & Defense**：诈骗检测、让 AI 安全处理钱，最直接对应。
- **03 Privacy & Private AI**：如果用了 TEE、只比对不搬资料。
- **05 AI Swarms**：如果诱饵、追踪、分级拆成多个 Agent 协作。
- 表单可以多选赛道，最后再定。

## 4. 商业模式（比赛后）

模式参考 Apate 和 TRM：**卖情报给有合规义务的机构**。

| 客户 | 付费理由 | 收费方式 |
|---|---|---|
| 交易所 | 反洗钱合规，避免收到赃款被冻结 | 订阅 + 按 API 用量计费 |
| 钱包 App | 在用户转账给诈骗地址前提醒，减少客诉 | 按调用量计费 |
| 跨链桥 / DEX / Intents 做市商 | 避免成为洗钱通道，降低监管风险 | 订阅 |
| 银行 / 电信 | 法币端的诈骗关联情报（出金、电话号码） | 情报订阅 |
| 执法机关 | 证据包、资金追踪报告 | 免费或补助（建立公信力） |

**冷启动**：先对厂商免费订阅，用"命中数"和"冻结金额"当成绩，再对快速通报、证据包、API 额度收费。

## 6. 风险与对策

| 风险 | 对策 |
|---|---|
| **误报**：误伤正常地址 | 每个地址附证据和可信度等级；设申诉流程；L3 等级默认不推送 |
| **诽谤或施压的指控** | 公开的只有可验证的事实（时间、资金去向、有没有回应），不贴评价标签 |
| **跟真骗子互动的法律和人身风险** | 比赛版只用模拟诈骗方；真实上线前先找律师，并跟执法单位合作 |
| **骗子频繁换地址** | 地址聚类：同一来源分出去的地址一起标记（比赛后加强） |
| **厂商不来订阅** | 先免费，用成绩说服；优先找有合规压力的交易所 |
| **时间不够** | 先保住主流程（诱饵 → 合约 → 订阅命中 → 记录表），TEE 和多链追踪排最后 |

## 7. 比赛后接着要做的事

**短期（1 个月内）**
1. 等评审结果（11/16–18）。不管结果如何，都整理评委意见。
2. 接上真实的诈骗来源：
   - 让用户把诈骗讯息、截图转发进来，像反诈专线的回报入口。
   - 诱饵 Agent 接上 Telegram 和 WhatsApp，去对接真实的骗子。
3. 找 1–2 个试点：一个钱包 App 或一个小型交易所，免费订阅。
4. 找律师看清楚：跟骗子互动、发布地址、公开响应记录，在各个司法管辖区的法律风险。

**中期（1–3 个月）**
5. 地址聚类和多链追踪（EVM、Tron、BTC、Solana）。
6. 证据包格式标准化，符合执法单位能直接用的格式。
7. 研究跟 TRM Beacon Network 这类现有网络互通，或者定位成它们在 DeFi 和跨链这段的补充。
8. 申请 NEAR Foundation 等生态补助。

**长期**
9. 推出给电信和银行的法币端情报（电话号码、出金账户）。
10. 订阅收费上线；准备种子轮的材料（参考 Apate 的路径）。
