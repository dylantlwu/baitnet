## 1. 一句话定位

**AI 诱饵从骗子嘴里套出收款地址，经人工复核后写进 NEAR 链上的警报登记表；AI 代理付款前、NEAR Intents 换币前都会先查这张表，在钱跑掉之前拦下。专家可以在训练台上纠正 AI 诱饵，让它越来越会套话。**

## 4. 两条主数据流

**A. 情报流（反诈主线）**
1. 骗子在对话里给出收款地址。来源可以是骗子 AI、接管骗子的真人，或者上传的真实聊天记录。
2. 系统每句话都实时抽取，生成"地址草稿"。
3. 防投毒过滤：交易所热钱包、跨链桥合约、代币合约（如 USDT）、新开的账户会被拦下。
4. 防混淆检查（D33）：别的合约、非常活跃的地址、查不到的地址、骗子起疑后才给的地址、链名和地址格式对不上的，挂黄色警告，复核人必须逐条勾"我已核实"才能通过（服务器不勾就返回 409）。
5. **人工复核通过才上链**。链上只存地址、链名、等级和证据的 hash；完整对话加密存在本机。
6. 守卫和 Vault 立刻生效：AI 代理拒签、链上付款失败、Intents 拒绝报价。

**B. 训练流（让诱饵越来越好）**
1. 专家在竞技场开训练模式，给诱饵的回复评分；说得不好的，直接改写成"应该这样说"。
2. 审核者通过后，这条改写进入话术库，版本号加 1。
3. 诱饵每次回复前，按骗局类型、阶段和标签从话术库检索示例。
4. 每条通过的改写自动变成回归用例，`pnpm eval` 会给出改进曲线。
5. 导出：只导出诱饵一方的数据，给以后微调模型用。

## 5. 技术栈

- **链**：NEAR，合约用 Rust（near-sdk 5.30）。本地用 sandbox；测试网已部署（`registry.baitnet-651f.testnet`、`vault.baitnet-651f.testnet`）。Intents 部分用样例数据（Intents 没有测试网）。
- **后端**：TypeScript 和 Node 22.22 以上；SQLite 用 Node 内置的 `node:sqlite`；near-api-js 7。
- **前端**：Vite、React 19、TypeScript；图表是手写的 SVG，没有用 UI 框架。
- **大模型**：优先 NEAR AI Cloud，其次 Claude，没有 key 时用规则引擎。TEE 证明面板调用 NEAR AI Cloud 的 attestation 接口。
- **部署**：Railway，从 GitHub main 自动部署，线上连测试网合约，`BAITNET_AUTH=on`（邀请链接登录）。
- **为什么不用向量库**：数据量小，而且本来就有类型、阶段、标签，按标签检索更准，也不影响离线运行。检索做成了接口，数据超过一千条时可以换成 sqlite-vec。

## 6. 隐私与安全设计

- **上链的只有公开信息**：诈骗地址、证据 hash。电话、微信号、姓名一律不上链，也不以 hash 的形式上链，因为这类信息很容易被穷举还原。
- **上传的聊天记录先打码再分析**：身份证号、手机号、银行卡号、中文姓名、微信号或 QQ 号、地址都会被打码。原文用 AES-256-GCM 加密存在本机，交给大模型的只有打码后的版本。
- **诱饵防护**：诱饵的回复如果出现个人资料、助记词或私钥，或者答应付款、点链接，都会被拦下改写。真人耳语坏指令也带不偏它。
- **诱饵不开天眼**：骗子的真人卡、面具和心智不进诱饵的提示词；人类扮诱饵时网页也不显示。
- **防投毒 + 防混淆**：已知机构地址名单、链上合约和活跃度查询、账户年龄、起疑检测、人工复核。
- **只训练诱饵**：骗子一方的数据不导出，避免这套系统变成"诈骗话术生成器"。

## 7. 运行模式

| 模式 | 链 | 对话引擎 | 用途 |
|---|---|---|---|
| `pnpm demo`（离线，默认） | 本机 sandbox，每次启动都会重建 | 规则引擎 + 回放 | 本机体验、评委初筛、没有 key 的时候 |
| `pnpm demo testnet` | NEAR 测试网（已部署） | 规则引擎或大模型 | 对外展示链上记录 |
| `pnpm demo live` | 同上 | 大模型 | 真正的 AI 对练和评测 |
| 线上 Railway | NEAR 测试网 | 大模型 | 同事用手机练习、评委看线上版 |

端口：后端默认 8787、前端默认 5173，可以用 `BAITNET_SERVER_PORT`、`BAITNET_WEB_PORT` 改。后端端口被占用时 demo 一开始就报错退出。

训练数据（`data/training.sqlite`、会话、证据）**重启不会丢**，每次启动都会自动备份；只有 `pnpm demo --fresh` 才会彻底清空。

## 8. 现状评估（实话）

**已经可靠的**
- 整条情报链路和训练链路，在本地链和测试网上都实际走通过（接管 → 抽取 → 复核 → 上链 → 拦截 → 改写 → 审核 → 回归通过）。
- 06 赛道的三项硬要求都有实际演示：钱包守卫、只能调用单一合约的 function-call key、被注入的 agent 付款被拦下。
- 评测（2026-11-11）：
  - 规则模式 48/48 拿到地址、泄露 0、投毒 13/13 被过滤。
  - 大模型 real 模式 42/48 拿到地址、泄露 0、被带偏 1。
  - 骗子怀疑度校准：正常诱饵 4.8，轻微露馅 55，明显露馅 85（12 局只拿到 2 个地址，5 局骗子跑了）。说明"不被发现是 AI"这条原则现在能量化。
- 全新环境验收：从 clone 到 `pnpm demo --ci` 通过，主流程可用。

**要清楚的局限**
1. **规则模式的评测分数不能代表 AI 水平**，只能证明流程是通的。真实水平看 `--live --real` 的结果。
2. **GitHub CI 目前跑不起来**：GitHub 账户因账单问题被锁，需要 Dylan 在 GitHub 的 Billing 设置里处理；本机的 typecheck、测试、`demo --ci` 都通过。
3. 链上查询（D33）用公共免费节点，偶尔超时，会显示"查不到"警告，需要复核人自己看。
4. Intents 资金追踪用的是样例数据（Intents 没有测试网，Explorer API 需要合作方 JWT）。
5. 人设卡、骗子真人卡还没经过反诈专家审阅；"轻微露馅"多少分该触发收手，要等专家的手感来定。
6. macOS 上 sandbox 依赖 liblzma（启动脚本已自动处理）；`data/` 会越来越大，以后需要定期清理。

**竞品与差异化**：HAPI Protocol 已经在 NEAR 上做了链上风险地址库。我们的差异在于：①情报由 AI 诱饵主动套取，并附证据 hash；②订阅方在本地比对，不交换用户资料；③专家训练闭环，效果可以量化；④会追踪 NEAR Intents 的跨链出口；⑤给 AI 代理用的付款前检查，以及 Vault 合约的链上硬拦截。
