## 1. 目标
让专家在**自己每天用的聊天软件**里跟 AI 斗智：像跟真人聊天一样自然，同时随手就能纠正 AI。每一次纠正都沉淀进话术库，并且能在成绩单上看到效果。

## 2. 角色与玩法

| 玩法 | 专家扮演 | 机器人扮演 | 产生的训练数据 |
|---|---|---|---|
| **攻**：找诱饵的弱点 | 骗子（精聊专家） | 诱饵 AI | 对诱饵回复的评分、改写，以及被突破的案例 |
| **守**：示范怎么应对 | 受害者 / 诱饵（反诈专家） | 骗子 AI（照剧本出招） | 专家自己说的话可以一键存为"好话术" |
| **审**：把关 | 审核者（Dylan） | — | 审核改写；把地址复核后上链 |

依然**只训练诱饵**（D15）：骗子 AI 只照剧本出招，不从专家那里学。

## 3. 架构

```
Telegram ─┐
飞书/Lark ─┼─▶ 渠道适配层 ChannelAdapter ─▶ 会话路由（一个私聊对应一场进行中的会话）─▶ 竞技场引擎（现成）
网页      ─┘        ▲                                                       │
                    └─── 发消息 / 显示"正在输入" / 按钮 / 卡片 ◀───────────────┘
                                          话术库 · 审核 · 抽取 · 上链 · 评测（全部现成）
```

- 新增的只有**适配层**和**会话路由**，竞技场引擎、训练库、上传分析都复用现有代码。
- 适配层接口：`onMessage(user, chat, text|images|file)`、`onButton(user, chat, payload)`、`send(chat, text, buttons?)`、`typing(chat)`、`editButtons(msg)`。Telegram 和飞书各实现一份。
- 会话上会多记一个 `channel: {kind: "web"|"telegram"|"lark", chatId}`，网页后台可以看到所有渠道的会话。

## 4. 在 IM 里怎么用（以 Telegram 为例）

| 操作 | 方式 |
|---|---|
| 第一次绑定 | 发 `/start <邀请码>`，或者直接点邀请链接 `t.me/<机器人>?start=<码>` |
| 开一场 | 发 `/new` → 选「我当骗子 / 我当诱饵」→ 选骗局类型 → 选剧本（或者随机） |
| 聊天 | 直接打字。机器人会先显示"正在输入…"，按句子长度停顿 2–8 秒再回复，偶尔把一段话拆成两条发 |
| 当场纠正（攻） | 诱饵的每句话下面有 👍 👎 ✏️。点 ✏️，机器人会说"请回复更好的说法"，你回一句，就生成一条改写，等审核 |
| 存好话术（守） | 你自己发的每句话，机器人可以在后面附一个 ⭐ 按钮，点了就存成好话术候选 |
| 耳语 | `/w 内容`，只对你这一场里的 AI 生效 |
| 换模式 | `/mode`：AI 自己说、我接管、只看 |
| 结束 | `/end` → 给这一场打 1–5 分，写一句评语 |
| 上传素材 | 直接转发截图（多张会自动合成一份）或聊天记录文件给机器人，它回一张分析卡片，带「存为剧本」按钮 |
| 查看 | `/status` 看今日额度和本场抽到的地址；`/help` 看帮助 |

**审核者**（Dylan）会收到机器人推送的卡片：
- 待审改写：并排显示坏的说法和好的说法，按钮 ✅ / ❌；
- 抽到的地址：按钮 ✅ 上链 / ❌ 驳回；
- 每天一份小结：新增了多少改写、多少地址，回归通过率是多少。

## 5. 安全与隐私
- **只和已绑定的同事说话**：陌生人发消息一概不回。这样不会被真骗子或者路人利用，也不会消耗额度。
- **每人每天有大模型调用上限**，所有操作都记审计日志（沿用 D20 的设计）。
- **⚠ 隐私风险（需要你决定）**：通过 Telegram 或飞书上传的截图、聊天记录，会**先经过这两家公司的服务器**，Telegram 的普通聊天也不是端到端加密的。对练的内容本身没问题，因为都是虚构的；但**真实受害者的聊天记录**经过第三方，就有个人资料外流的风险。见 §8 第 1 题。
- 机器人的 token、飞书应用密钥都只放在服务器的环境变量里。

## 6. 平台细节
- **Telegram**：用 Bot API 的长轮询模式，不需要公网回调地址。机器人可以跑在香港服务器上（大陆的服务器连不上 Telegram）。机器人由 **Dylan 本人**在 @BotFather 创建，把 token 交给服务器环境变量。
- **飞书 / Lark**：飞书和 Lark 是**两套租户**，各需要建一个企业自建应用，由**租户管理员**审批。用"长连接"方式接收事件，不需要公网回调地址。卡片支持按钮和表单，改写可以直接在卡片里填。
- 两家共用同一个适配层接口，所以第二家的工作量大约是第一家的一半。

## 8. 待确认的问题
1. **IM 能不能上传真实聊天记录？** 建议：IM 里可以上传，但每次上传前机器人先提示"会经过 Telegram/飞书服务器，含真实个人资料的请改用网页上传"；网页上传走我们自己的服务器，并且先打码。
2. **机器人对外的人设**：诱饵机器人叫什么、用什么头像？骗子机器人是否每个剧本换一个名字？（建议：诱饵固定叫"小林"之类的普通名字，骗子按剧本人设改显示名；但 Telegram 机器人不能按会话改名，所以骗子身份只在消息里体现。）
3. **要不要支持群聊围观？** 例如在一个群里，一位专家对练、其他人旁观并点评。建议赛后再做。
