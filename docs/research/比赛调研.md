## 0. 对产品决策有影响的结论

1. **主报 06 AI Security & Defense，加选 03 Privacy（要真的做了 TEE attestation 校验才选），05 Swarms 不建议选。** 06 的官方提示词里本来就写了"共享黑名单（blocklist），agent 可附证据回报"这一信号，和 BaitNet 的警报登记表几乎一样，契合度最高。05 的核心是"竞价/集体采购/经 Intents 结算的 agent 市场"，和我们关系弱。表单可以多选，但只算一个提交。
2. **demo 里必须补一段"钱包守卫拦截"场景**：06 提示词要求的三件事——agent 端包装器（block 拒签、warn 问人）、只用限定单一合约的 function-call key（README 说明限制）、**被 prompt 注入的 agent 试图付款给已知坏地址并被拦下、展示日志**。把 BaitNet 登记表当作这个"已知坏地址"的来源，就同时满足了赛道要求和我们的故事。提示词仓库写明"可以换掉起始想法，但要保留 requirements 和 checkpoint"。
3. **README 和一键 demo 是初筛的命门**：Claude Code 和 Codex 先跑每个项目，做"可复现检查、功能核对、结构化报告、初步打分"。官方没公开它们的运行环境、有没有网络、给不给 API key、时间限制——所以要按"没有任何 key 也能跑"设计：LLM 调用要有离线/录制回放模式，Intents Explorer（需 JWT）要有本地样例数据回退，合约用测试网（已部署地址写进 README），不能依赖我们的私钥。仓库历史里不能有任何密钥。
4. **测试网完全可以**：官方明说不强制主网/测试网、不强制任何 NEAR 集成，测试网项目在所有赛道都合格；"自己写一个契合赛道的 NEAR 合约就够"。但 **NEAR Intents 没有测试网**，资金追踪那部分要用主网只读数据或样例数据；Intents Explorer API 需要 Partner Dashboard 的 JWT 且限速 5 秒 1 次，不能作为 demo 的硬依赖。
5. **撞题风险：HAPI Protocol 已经在 NEAR 上做了"白名单报告者写入的链上风险地址库"**，MyNearWallet、Jumbo Exchange 接入过。差异化必须讲清：①情报来源是 AI 诱饵对话（L1 一手证据，带证据 hash），②订阅方本地比对、不搬用户资料，③公开响应记录表，④追踪 NEAR Intents 跨链路径，⑤给 AI agent 用的付款前检查。另外 AI 生成的代码必须在 README 列出；比赛前已有代码要分开（2026-10-19 公告之后写的才算）。

### 06 AI Security & Defense（主推）
来源：https://github.com/nearai/near-hackathon-prompt-examples/blob/main/tracks/06-security.md
- 口号 "Trust, but verify"；目标"给 AI 钱，但不把所有钥匙交给它"。
- 起始想法：**交易对手检查服务**——agent 转账或调合约前查询，返回 allow / warn / block 及理由。
- 建议评分信号：账户年龄与活跃度；收款方是否合约、代码是否最近变过；本 agent 与对方的历史交互；**共享黑名单，agent 可附证据回报**。
- 要求：
  - agent 端包装器：block 时拒签，warn 时问人。
  - 用**只限一个合约的 function-call access key** 签名，不用 full-access key，README 解释 key 的限制。
  - **攻击 demo**：被 prompt 注入的 agent 试图付款给已知坏地址，被拦下，展示日志。
- 流程 checkpoint：先列出每个信号的数据来源和获取方式，再开始写。
- 注意：只有 function-call key 的账户不能转 NEAR、不能加 key，gas allowance 用完会把自己锁住。
- 推荐资料：NEAR access keys 文档、OutLayer、NEAR AI Cloud verification、Agent API policies。
- 评审重点：**未找到**单独的赛道评审标准。

### 03 Privacy & Private AI（可选加报）
来源：https://github.com/nearai/near-hackathon-prompt-examples/blob/main/tracks/03-privacy.md
- 口号 "Private by design"；起始想法是私密记账审计（上传票据，NEAR AI Cloud 模型分类，证明在 TEE 里跑）。
- 要求：通过 OpenAI 兼容 API `https://cloud-api.near.ai/v1` 调 NEAR AI Cloud，key 放 `.env`；从 models 端点选 TEE 托管模型；**用新随机 nonce 拉 attestation 报告并按文档校验**，界面显示"Verified"面板列出每项检查；**响应返回后服务端不留任何数据**，README 和代码都要体现；附虚构样例数据让评委不用真数据就能跑。
- 对 BaitNet：如果诱饵 Agent / 证据处理真跑在 NEAR AI Cloud 并做了 attestation 校验，才值得报。注意这需要 API key，初筛环境未必有 → 需要录制的 attestation 样例做回退。

### 05 AI Swarms（不建议）
来源：https://github.com/nearai/near-hackathon-prompt-examples/blob/main/tracks/05-swarms.md
- 口号 "Many agents, one economy"；起始想法是 GPU 小时团购群：买方 agent 汇集需求，对卖方 agent 做密封竞价，经 NEAR Intents 结算。
- 要求：每个 agent 一个子账户（如 buyer-1.swarm.testnet）；协调者合约/服务负责开轮、收密封出价、揭示、选赢家；先写 RULES.md；模拟模式 20 买方 + 5 卖方、无 LLM 调用；实时页面显示轮次、出价、清算价。
- 对 BaitNet：核心是"市场/竞价/结算"，我们只是多 agent 分工，不是经济协调，契合度低。若只是把诱饵/追踪/分级拆成子账户 agent，最多算加分点。

## 4. 规则

来源：https://nearhackathon.com/HACKATHON.md 、https://nearhackathon.com （FAQ）
- **一人多项目**：最多 2 个**相互独立**的项目，每个 README 都要写明另一个。
- **团队人数**：单人或团队，选项 1 / 2–4 / 4–6 / 6–8 / 8+，无上限说明。
- **AI 写代码**：**允许**，但要在 README 列出 AI 生成的代码。
- **赛前已有代码**：2026-10-19 公告之后写的代码才算，之前的提交视为基线。已有项目不能原样提交；在已有项目上做新功能可以，但要用专门分支，或打 `pre-hackathon` 与 `hackathon-submission` 两个 tag，并在 README 链接 diff。自己赛前写的库算基线。
- 每个 repo 只能提交一次；团队保留全部权利，组织方获得项目名、截图、视频、repo 链接的非独占宣传权。
- 提交不需要连接钱包，只填 NEAR 账户地址。

## 5. 技术可行性

### 5.1 NEAR Intents 历史数据
- **Intents Explorer API**：`GET https://explorer.near-intents.org/api/v0/transactions`。来源：https://docs.near-intents.org/near-intents/integration/distribution-channels/intents-explorer-api 、https://docs.near-intents.org/api-reference/get-transactions
- **要 key**：所有请求都需 JWT（Bearer），从 Partner Dashboard https://partners.near-intents.org/ 获取。**是否免费、是否需审批：未找到**。
- **限速**：每个 partner 每 5 秒 1 次，超出返回 429。
- **能否按地址查**：没有专门的 sender/recipient 过滤参数，但 `search` 参数可匹配 **deposit address、recipient、sender 或交易 hash**——可以按地址查。另有 fromChainId/toChainId、fromTokenId/toTokenId、statuses、时间范围、USD 金额区间、分页（lastDepositAddress/lastDepositMemo，最多 1000 条/页）。
- 返回字段含 originAsset/destinationAsset、depositAddress、recipient、refundTo、senders、amountIn/Out(USD)、status、intentHashes、nearTxHashes、originChainTxHashes、destinationChainTxHashes——够做"资金经过 Intents 去了哪条链"。
- **范围限制**：只覆盖 **1Click Swap** 交易，不是全部 Intents 活动。
- **无需 key 的公开替代：未找到**。→ demo 必须带本地样例数据回退。

### 5.2 NEAR AI Cloud
- **公开可用**：在 cloud.near.ai 自助注册、买 credits、生成 API key；OpenAI 兼容，base URL `https://cloud-api.near.ai/v1`。来源：https://docs.near.ai/cloud/quickstart
- **免费额度**：文档未提免费额度（需购买 credits）；HACKATHON.md 说加入 NEAR Builders 可领 **10 美元** credits。
- **Attestation 接口：有**。`GET https://cloud-api.near.ai/v1/attestation/report?model=...&nonce=...&signing_algo=ecdsa|ed25519`；通用模型**不需要 API key**。返回 Intel TDX quote、event_log、signing_address、可选 NVIDIA GPU 证据等；校验步骤包括用 DCAP 验证 quote、确认 report data 绑定 nonce 和 signing_address、重放 event_log 对 RTMR3 等。来源：https://docs.near.ai/cloud/verification/cloud-api/model-attestations.md
- **回复签名**：`GET https://cloud-api.near.ai/v1/signature/<CHAT_ID>?signing_algo=...`，**需要 API key**。来源：https://docs.near.ai/cloud/verification/cloud-api/response-signatures.md
- 浏览器验证页：https://cloud.near.ai/verify ；官方校验示例：https://github.com/near-examples/nearai-cloud-verification-example
- 注意：同一模型的实例共用签名 key，签名匹配不能证明报告和回复出自同一实例。

### 5.3 near-sdk-rs 与测试网部署
- **当前稳定版：near-sdk 5.30.1**（2026-11-05 发布；5.30.0 于 10-27）。来源：https://crates.io/crates/near-sdk
- 部署（来源：https://docs.near.org/smart-contracts/release ）：
  ```bash
  cargo near build
  near create-account <accountId> --useFaucet
  near deploy <accountId> <path_to_wasm>
  near call <contractId> <initMethod> '<args>' --useAccount <accountId>
  ```
  NEAR CLI 默认网络即 testnet。重新部署会覆盖逻辑但保留状态。

- **AI 诱饵类**：HCL GUVI Hackathon 2026 的 "Agentic Honeypot"（AI 人设与攻击者对话、导出情报，非区块链，https://shreyansh9026.github.io/case-studies/agentic-honeypot.html ）；学术上有 LLM 诱骗系统论文（https://arxiv.org/abs/2509.08493v1 ）。
- **往届 NEAR 黑客松中的同类反诈/黑名单项目：未找到。**
- **差异化建议**：HAPI 等是"报告者人工提交 + 风险分"；BaitNet 的不同点是 ①**情报源头是 AI 诱饵主动套出**的一手证据（L1，链上存证据 hash），②**订阅方本地比对、不交换用户资料**，③**公开响应记录表**（谁收到警报、多久响应），④**追踪 NEAR Intents 跨链出口**，⑤直接接 06 要求的 **agent 付款前检查 + function-call key 限权**。README 里可以主动提 HAPI 并说明互补关系，比被评委发现更好。
