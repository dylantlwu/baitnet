# BaitNet 云端部署说明（给 Dylan）

> 适用决策：D18（香港云主机 + Caddy HTTPS + 每日备份）、D19（NEAR 测试网）、D20（邀请码登录）、D21（NEAR AI + Claude）。

## 1. 买一台香港云主机

推荐 **阿里云「轻量应用服务器」香港** 或 **腾讯云「轻量应用服务器」香港**。两家都不需要备案，大陆和海外访问都还可以。

| 项目 | 选什么 |
|---|---|
| 地域 | 中国香港 |
| 配置 | **2 核 2G** 就够了（带宽 30M 左右、40–60G SSD） |
| 系统镜像 | **Ubuntu 22.04 或 24.04**（选纯系统，不要选应用镜像） |
| 价格 | 大约 **每月 ¥25–60** 或 **每年 ¥250–600**。新用户首年常有活动价，按月和按年差别很大，**以官网为准** |
| 时长 | 至少买到 11/25（评审在 11/16–18，托管 demo 建议维持到 11/25），按月买就行 |

买好以后，在控制台记下：
- **公网 IP**（例如 `47.x.x.x`）；
- **防火墙 / 安全组**：放行 TCP **22、80、443**，最好再放行 UDP 443（HTTP/3）。轻量服务器的防火墙在实例详情页的"防火墙"标签里。**不要开放 8787**。

> 香港节点不需要 ICP 备案就能用 IP 或境外域名访问。但**微信对没有备案的域名可能会拦截**，见第 7 节。

## 2. 配置 SSH key（只做一次）

在**你的 Mac** 上：

```bash
# 1) 没有 key 就生成一把（一路回车；建议设置密码短语）
ls ~/.ssh/id_ed25519.pub || ssh-keygen -t ed25519 -C "dylan-baitnet"

# 2) 显示公钥，整行复制
cat ~/.ssh/id_ed25519.pub
```

然后在云控制台里添加：
- 阿里云：轻量服务器 → 实例 → 远程连接 → 密钥（或在"密钥对"里导入公钥），绑定到实例；
- 腾讯云：轻量服务器 → SSH 密钥 → 导入已有密钥 → 绑定实例。

绑定后测试一下（第一次连接会问是否信任主机指纹，输入 `yes`）：

```bash
ssh root@<公网IP> 'uname -a'
```

可选，但建议做：在 `~/.ssh/config` 里加一段，以后直接 `ssh baitnet` 就能连上：

```
Host baitnet
  HostName <公网IP>
  User root
  IdentityFile ~/.ssh/id_ed25519
```

能用 key 登录以后，**把密码登录关掉**：在服务器上编辑 `/etc/ssh/sshd_config`，设置 `PasswordAuthentication no`，然后执行 `systemctl restart ssh`。改之前先确认 key 登录确实可用。

## 3. 第一次部署（大约 15 分钟）

### 3.1 把部署套件传上去，初始化服务器

在你的 Mac 上，进入仓库目录：

```bash
cd ~/BaiNet
scp -r deploy root@<公网IP>:/root/baitnet-deploy
ssh root@<公网IP>
```

在**服务器**上执行（三种写法任选一种）：

```bash
# A. 没有域名：自动使用 <ip>.sslip.io，并自动申请证书
sudo bash /root/baitnet-deploy/setup-server.sh --basic-auth team

# B. 有域名：先在 DNS 里加一条 A 记录指向服务器 IP，等它生效后再执行
sudo bash /root/baitnet-deploy/setup-server.sh --domain baitnet.example.com --email 你的邮箱 --basic-auth team

# C. 登录功能上线以后：去掉 --basic-auth
```

`--basic-auth team` 会让你设置一个全站密码（至少 10 位），在登录功能上线前用来保护整个站点。

脚本会自动完成下面这些事（可以重复执行）：
- 安装 Node 22（≥22.22.2，会校验 SHA256）、pnpm、Caddy、sqlite3；
- 新建系统用户 `baitnet`。代码放在 `/opt/baitnet`（`releases/` 里存放各个版本，`app` 指向当前版本），数据放在 `/var/lib/baitnet`；
- 从模板生成 `/etc/baitnet/env`（权限 600），并自动生成会话密钥和证据加密密钥；
- 配置 systemd 服务 `baitnet`：开机自启，崩溃后 3 秒自动重启；
- 配置 Caddy：自动申请 HTTPS 证书，反向代理到 `127.0.0.1:8787`，SSE（实时日志）不缓冲；
- 配置定时任务：每天 03:30 备份（保留 14 天），每 5 分钟做一次健康检查；
- 配置防火墙：只开放 22、80、443。

### 3.2 填写密钥和测试网账户

```bash
sudo nano /etc/baitnet/env
```

需要填写的项（模板里每一项都有说明，模板文件是 `deploy/env.production.example`）：
- `NEARAI_API_KEY`、`ANTHROPIC_API_KEY`；
- 测试网：`REGISTRY_CONTRACT_ID`、`VAULT_CONTRACT_ID`，以及 `OWNER_` / `REPORTER_` / `AGENT_` / `RESPONDER1_` / `RESPONDER2_` 开头的 `ACCOUNT_ID` 和 `PRIVATE_KEY`。这些值从后端 A 的 `.env.testnet` **复制**过来，复制时不要经过聊天软件；
- `BAITNET_LLM_DAILY_LIMIT`：每人每天的大模型调用上限。

**整份 `/etc/baitnet/env` 要另存一份到你的密码管理器里**。里面的 `BAITNET_EVIDENCE_KEY` 一旦丢失，加密的证据就再也解不开了；每日备份里**故意没有**包含这个文件。

### 3.3 从你的 Mac 推送代码

```bash
cd ~/BaiNet
deploy/push.sh root@<公网IP>          # 或者先设置 export BAITNET_DEPLOY_HOST=root@<公网IP>
```

push.sh 会依次做这些事：
1. 在本机做密钥扫描，并检查有没有源文件被 `.gitignore` 误忽略；
2. 只上传 git 会提交的文件。`.env`、`data/`、`node_modules` **不会**离开你的电脑；
3. 在服务器上安装依赖、构建网页、切换到新版本、重启服务；
4. 等 `/health` 返回正常。如果 30 秒内没有正常，会**自动回滚**到上一个版本，并打印日志。

想先看看会上传哪些文件：`deploy/push.sh root@<IP> --dry-run`。

### 3.4 打开网站

浏览器打开 setup 最后打印的地址，例如 `https://47-1-2-3.sslip.io`。第一次访问时 Caddy 会去申请证书，可能要等十几秒。

## 4. 生成第一个 reviewer 邀请码

> 前提：登录功能已经接入 server（见第 0 节）。在那之前，命令能生成邀请码，但网页不会要求登录。

在服务器上：

```bash
sudo baitnet-invite --name Dylan --role reviewer
```

输出类似这样：

```
  邀请已创建  Dylan（reviewer）
  邀请码：XXXXXXXXXXXX   ← 只显示这一次
  一点即登链接：https://<你的地址>/#/login?code=XXXXXXXXXXXX
```

- 邀请码在数据库里只存 hash，**只会显示这一次**，请立即发出去或保存好；
- 其他命令：`sudo baitnet-invite --list`（列出邀请，码会打码）、`sudo baitnet-invite --revoke <码或ID>`（吊销，对方的登录立即失效）；
- 之后的邀请由 reviewer 在网页的管理页里生成（专家用 `--role expert`）。网页管理页会直接显示二维码。

本机也能生成（写入 `./data/auth.sqlite`）：`pnpm invite --name 测试 --role expert`。

## 5. 把邀请链接或二维码发给同事

- **链接就是登录凭证**。只能私聊发给本人，**不要发到群里**，也不要贴在公开文档里。
- 一个人一个码，名字写真实名字，这样审计日志才能对上人。
- 二维码：在网页管理页里直接给对方扫，或者截图私发。**不要用在线二维码生成网站**，否则链接会被第三方看到。
- 有人离职或者链接泄露了，立刻执行 `--revoke`。
- 在登录功能上线前用的是全站密码（`--basic-auth`），需要把用户名和密码**分开发**，比如链接发微信、密码当面告诉或电话说。

## 6. 日常运维

### 更新版本

```bash
cd ~/BaiNet && deploy/push.sh root@<IP>        # 部署当前工作区
deploy/push.sh root@<IP> --rollback            # 发现问题，切回上一个版本
```

服务器上保留最近 5 个版本。数据在 `/var/lib/baitnet`，切换版本不会影响数据。

### 改配置

```bash
sudo nano /etc/baitnet/env && sudo systemctl restart baitnet
```

### 看日志

```bash
journalctl -u baitnet -f                  # 应用日志（实时）
journalctl -u baitnet --since "1 hour ago"
journalctl -u caddy -f                    # HTTPS 和证书
tail -f /var/log/caddy/baitnet.log        # 访问日志
journalctl -t baitnet-health              # 健康检查失败和自动重启的记录
cat /var/lib/baitnet/backups/backup.log   # 备份记录
```

### 健康检查和监控

- 健康检查端点：`GET https://<你的地址>/health`，正常时返回 `{"ok":true,...}`。开了全站密码时，需要从服务器本机检查：`curl localhost:8787/health`；
- 服务器上随时可以执行 `sudo baitnet-healthcheck` 查看状态。cron 每 5 分钟检查一次，连续 2 次失败会自动重启服务，并写进 journal；
- 外部监控（可选，建议做）：用 UptimeRobot（免费，每 5 分钟一次）或云厂商自带的"云监控 / 站点监控"盯着 `/health`，挂了会发邮件或短信提醒你。开了全站密码时，可以在监控设置里填上用户名和密码；
- 磁盘剩余空间低于 1 GB 时，健康检查会报警。

### 备份

- 自动备份：每天 03:30（服务器时间）用 `VACUUM INTO` 备份 `training.sqlite`、`auth.sqlite` 等全部 SQLite 库（即使服务正在运行，备份也是一致的），另外把 `evidence/`、`arena/`、`eval/`、`training-export/`、`conversations/` 打包。保存在 `/var/lib/baitnet/backups/daily/<日期>/`，**保留 14 天**；
- 手动立刻备份一次：`sudo -u baitnet env BAITNET_DATA_DIR=/var/lib/baitnet baitnet-backup`；
- **拉回本机**（建议每周一次，重要操作前也拉一次）：
  ```bash
  deploy/pull-backups.sh root@<IP>        # 保存到 ~/BaiNet/backups/<IP>/daily/（这个目录已被 git 忽略）
  ```

### 恢复

```bash
sudo systemctl stop baitnet
cd /var/lib/baitnet
sudo -u baitnet cp backups/daily/<日期>/training.sqlite training.sqlite
sudo -u baitnet rm -f training.sqlite-wal training.sqlite-shm
# 需要的话 auth.sqlite 也按同样方法恢复；文件类数据：
sudo -u baitnet tar -xzf backups/daily/<日期>/files.tar.gz -C /var/lib/baitnet
sudo systemctl start baitnet
```

换服务器恢复：先在新机器上跑 setup-server.sh，把旧的 `/etc/baitnet/env` 放回去（从密码管理器里取），把 `backups/` 传上去后按上面的步骤恢复，最后执行 `push.sh`。

## 7. 在微信里打开链接的注意事项

- **没有备案的域名（包括 `sslip.io`）在微信内置浏览器里可能被拦截**，或者弹出"非微信官方网页，请确认是否继续访问"、"如需浏览，请长按网址复制后使用浏览器访问"之类的提示。被举报过的域名甚至会直接无法打开。
- 建议同事这样打开：
  1. **用手机浏览器打开**（Safari、Chrome、系统浏览器都可以），把链接长按复制后粘贴进去；或者
  2. 在微信里点右上角 **"…" → "在浏览器打开"**（iOS 是"在 Safari 中打开"）。
- 发链接的时候可以顺便附一句："如果微信打不开，请点右上角 … 选在浏览器打开"。
- 在浏览器里打开后，可以"添加到主屏幕"，以后像 App 一样点开就行（PWA 需要前端加上 manifest，进度见第 9 节）。
- 如果以后想在微信里稳定打开：需要一个**已经 ICP 备案的域名**，而且服务器要放在大陆。这跟"香港节点、免备案"的方案冲突，比赛期间不建议。

## 8. 安全注意事项

- **密钥只放在两个地方**：服务器的 `/etc/baitnet/env`（600，root）和你的密码管理器。不要发微信，不要提交到 git（push.sh 和 pre-commit 钩子都会扫描）。
- 测试网私钥虽然不值钱，但 reporter 的 key 能往登记表写警报，泄露了就等于别人能冒充你们写警报。agent 用的是**只能调用 vault.pay 的 function-call key**。
- 大模型 key 是花钱的：务必设好 `BAITNET_LLM_DAILY_LIMIT`，并在 NEAR AI / Anthropic 控制台里**设置月度预算上限**。
- 登录上线前必须加 `--basic-auth`。上线后，邀请链接要一人一码，人走了就吊销。
- 只开放 22/80/443；8787 在云安全组和 ufw 两层都不开放（server 支持 `HOST=127.0.0.1` 之后，还会只监听本机）。
- SSH 只用 key 登录，关闭密码登录（见第 2 节）。想更严格的话，可以在云安全组里把 22 端口只放行你常用的 IP。
- 系统更新：建议每周执行一次 `sudo apt update && sudo apt upgrade -y`。Ubuntu 默认开启了 unattended-upgrades 自动安全更新。
- 服务以 `baitnet` 用户运行，systemd 做了加固：只能写 `/var/lib/baitnet`，不能读 `/home`。
- 证据原文是加密存储的。证据密钥丢了数据就恢复不了，泄露了就等于证据泄露，所以要像对待数据库密码一样保管。

## 9. 本机验证结果与待办（11/9）

在本机（macOS）上用生产配置把 server 单端口跑了一遍（`NODE_ENV=production`、`BAITNET_AUTH=on`、`BAITNET_WEB_DIST=apps/web/dist`、端口 8790、独立数据目录）：

| 检查项 | 结果 |
|---|---|
| `/health` | ✓ `{"ok":true,...}` |
| 浏览器访问 `/` | ✓ 返回 index.html（API 客户端访问 `/` 仍然返回 JSON） |
| 静态资源 `/assets/*.js` / `.css` | ✓ 200，`cache-control: immutable` |
| 前端深层路径 | ✓ 回退到 index.html；不存在的 `/assets/x.js` 返回 404 |
| SSE `/events` | ✓ `text/event-stream`、`no-transform`、`x-accel-buffering: no`；追加一条事件后约 0.6 秒推送到客户端 |
| SSE `/arena/sessions/:id/events` | ✓ 头部正确，能收到数据 |
| 登录页、`/auth/login` | ✗ **还没有接入**：`/auth/me` 返回 `authEnabled:false`，`/auth/login` 返回 404（按 D25 暂停中，属于 B1 的工作） |
| PWA `manifest.webmanifest` | ✗ 还没有（前端） |
| 服务器监听地址 | server 目前监听所有网卡，不认 `HOST=127.0.0.1`。依靠防火墙挡住 8787；建议 B1 支持 `HOST` |
| Caddy、systemd、ufw、apt | 本机没法验证（没有 Linux，也不能连服务器）。脚本已通过 `bash -n` 语法检查；Caddyfile 会在服务器上由 `caddy validate` 校验，校验失败时 setup 会停下来 |
