# 防混淆检查（D33）

拍板：Dylan，2026-11-11。

## 要防的情况

骗子发现对面是诱饵，或者起了疑心以后，故意发来不相干的地址，想让我们把无辜的人或机构标成诈骗地址。比如：

- USDT、USDC 的合约地址，交易所的热钱包；
- 别人的老钱包；
- 嘴上说「TRC20」，给的却是 0x 开头的地址。

我们宁可漏报，也不能冤枉人。

## 原则

- **能确定的直接拦**：已知地址名单命中，或者是代币合约，就设 `filteredReason`，不上报。这和现在的做法一样。
- **不确定的挂警告**：设 `AlertDraft.warnings`，地址仍然待审。审核员必须逐条确认警告才能通过，服务器也要校验，不能只靠前端。
- **查不到不等于没问题**：链上查询失败要挂 `unchecked` 警告，让审核员手动查。
- 警告只给团队看，不上链，也不发给对面。

## 四项检查

| # | 检查 | 结果 |
|---|---|---|
| 1 | **已知地址名单扩充**：补主流稳定币合约（USDT、USDC 在 Ethereum、BSC、Tron 上）、WETH、常见 DEX 路由、主要交易所热钱包 | 命中：拦截。每条都要在区块浏览器上核实，`source` 字段写核实用的网址。宁缺毋滥 |
| 2 | **是不是合约**：EVM 用 `eth_getCode` 查，BEP-20 提示查 BSC，其他查 Ethereum，两条链都可以查；Tron 用 TronGrid 的 `getcontract` | 是代币合约（`totalSupply()` 能调通）：拦截。其他合约：`contract` 警告 |
| 3 | **账户年龄和活跃度真查**：EVM 用 `eth_getTransactionCount`；Tron 用 `getaccount` 的 `create_time` | EVM 交易数 ≥ 10000，或 Tron 账户超过 730 天：`very-active` 警告（不拦截，骗子也可能用老号）。样例数据的旧行为保持不变 |
| 4a | **可疑时机**：这个地址出现之前，骗子问过「你是不是机器人、AI、警察」「你在测试我吗」「你是钓鱼的吧」之类（中英都要）；或者诱饵之前有一稿 `admitted-ai` 最终没被改掉 | `suspicion-before` 警告，写明是第几轮、说了什么 |
| 4b | **链和格式对不上**：骗子说的网络（TRC20、ERC20、BEP20、BTC、NEAR）和地址格式不符 | `chain-mismatch` 警告 |

## 网络和超时

- `BAITNET_EVM_RPC_URL`、`BAITNET_BSC_RPC_URL`、`BAITNET_TRON_API_URL` 有默认值，分别是 publicnode 的 Ethereum、BSC 节点和 `https://api.trongrid.io`。
- 设成 `off` 就不查。
- 每次查询超时 3 秒，失败挂 `unchecked` 警告，不报错中断。
- 测试和离线评测用桩，不访问网络。
- 不查的时候不挂 `unchecked`，否则离线演示里每个地址都会带警告。

## 审核

- 接口：通过一个带 `warnings` 的地址，请求必须带 `confirmWarnings: true`，否则返回 409，并告诉审核员要确认哪几条。
- 网页：
  - 地址卡片上用醒目的颜色逐条列出警告；
  - 点「通过」后，每条警告前都有勾选框「我已核实」，全部勾上才能提交。
- 评测自动审核（`eval-auto`）不会通过带警告的地址；报告里单独统计「挂警告」的数量。
- 用到同样检查的地方：
  - 对练（`packages/arena`）；
  - 上传分析（`packages/scriptlab`）；
  - M2 流水线（`apps/agent`）。

## 评测

新增 2 个剧本：

- **中文**：骗子先问「你是不是机器人」，然后发 BSC 上的 USDT 合约地址。应该被拦截，算 `poisonFiltered`。
- **英文**：骗子起疑心后说「send via TRC20」，给的却是一个新的 0x 地址。应该挂上 `suspicion-before` 和 `chain-mismatch` 警告，评测不会自动通过它。
